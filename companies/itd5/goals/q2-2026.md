# ITD5 — Flagship Agentic Stack roadmap

**Accountable owner:** Seamus Walsh, Founder & CEO  
**Roadmap window:** 28 August–27 November 2026  
**Mission:** Make the ITD5 Agentic Stack a dependable, repeatable operating foundation for ITD5 and its client delivery work.

This roadmap is ordered by dependency: make deployment reliable first, prove the operating model second, then use that foundation to deliver a client-facing product and productised services.

## Priority order

| Priority | Goal | Deadline | Required outcome |
|---|---|---:|---|
| P0 | G1 — Ship a reproducible, recoverable deployment | 11 September 2026 | A new Linux host can install, start, verify, back up, and recover the stack |
| P1 | G2 — Operationalise the ITD5 company in Paperclip | 25 September 2026 | ITD5 goals, agents, governance, and a bounded evidence-backed sprint run in Paperclip |
| P2 | G3 — Prove the client portal MVP | 23 October 2026 | One narrow client workflow is usable, secure, documented, and ready for a pilot |
| P3 | G4 — Productise secure service delivery | 27 November 2026 | WEEE/data-destruction and cybersecurity/transformation offers have repeatable delivery assets and pilot evidence |

**Status key:** [x] evidenced as delivered in the repository or merged work; [ ] still open. A checked item is not a substitute for live runtime verification.

## G1 — Ship a reproducible, recoverable deployment (P0)

**Accountable owner:** Seamus Walsh  
**Delivery owner:** CTO agent/technical delivery function, after G2 onboarding  
**Assurance:** QA agent/quality function  
**Deadline:** 11 September 2026  
**Dependencies:** Docker Engine or Docker Desktop with Compose v2, Git, curl, a browser, and access to a Docker-enabled Linux host for the final smoke test.

### Tasks

- [x] Replace the unreliable wrapper with the official Paperclip container image.
- [x] Standardise Compose around port 3100, `HOST=0.0.0.0`, `PAPERCLIP_HOME=/paperclip`, private exposure, authentication secrets, health checks, and persistent `data/paperclip` storage.
- [x] Add the idempotent one-line installer, launcher, diagnostics, validation, backup, Make targets, and CI workflow.
- [x] Document prerequisites, configuration, optional gstack installation, operator commands, persistence, and recovery.
- [ ] Run the stack on a Docker-enabled Linux host and record a successful health-checked smoke test.
- [ ] Perform a backup, destroy/recreate the container, restore the data, and record the recovery result.
- [ ] Pin and publish the first tested release reference after the live smoke and recovery tests pass.

### Acceptance criteria

- A clean Linux machine meeting the documented prerequisites succeeds with:
  `curl -fsSL https://raw.githubusercontent.com/5hay196/itd5-agentic-stack/main/scripts/install.sh | bash`.
  - The dashboard is reachable at the configured URL and `/api/health` reports healthy after startup.
  - Restarting the service preserves the Paperclip database, uploads, secrets, and workspace data.
  - `doctor.sh`, `validate.sh`, and the CI workflow pass; the live smoke-test and restore evidence are committed under the repository documentation.

  **Repository evidence:** [README.md](../../../README.md), [docker-compose.yml](../../../docker-compose.yml), [scripts/install.sh](../../../scripts/install.sh), [scripts/backup.sh](../../../scripts/backup.sh), and [the validation workflow](../../../.github/workflows/validate.yml). Live Docker verification remains open because the Docker daemon was unavailable during the initial implementation.

  ## G2 — Operationalise the ITD5 company in Paperclip (P1)

  **Accountable owner:** Seamus Walsh  
  **Delivery owner:** CEO agent, with CTO agent for implementation and CSO/QA agents for governance and release assurance  
  **Deadline:** 25 September 2026  
  **Dependencies:** G1 live smoke test; authenticated Paperclip instance; versioned ITD5 company, agent, goals, and governance definitions.

  ### Tasks

  - [x] Version the ITD5 company, goals, agent roles, operating guidance, and governance definitions in the repository.
  - [x] Define the intended CEO, CTO, CSO, and QA responsibilities in the operating documentation.
  - [ ] Claim the first Paperclip admin and configure the ITD5 company in the running instance.
  - [ ] Onboard the CEO, CTO, CSO, and QA agents and verify that each has the correct role and scope.
  - [ ] Run one bounded end-to-end sprint from goal to work item, review, QA evidence, and closure.
  - [ ] Establish a weekly operating retro and a monthly agent budget review with recorded outputs.

  ### Acceptance criteria

  - The ITD5 company and four named agent roles are visible in Paperclip and match the versioned definitions.
  - One bounded sprint has a written objective, owner, dependency record, review decision, QA evidence, and completed outcome.
  - The weekly retro and monthly budget review have named owners, a repeatable agenda, and retained records.
  - No agent is granted broader access than required for its role, and failed work is recoverable without losing the audit trail.

  ## G3 — Prove the client portal MVP (P2)

  **Accountable owner:** Seamus Walsh  
  **Delivery owner:** CTO agent/technical delivery function  
  **Assurance:** CSO agent for security; QA agent for acceptance testing  
  **Deadline:** 23 October 2026  
  **Dependencies:** G1 accepted deployment and backup path; G2 operating baseline; one selected pilot client workflow.

  ### Tasks

  - [ ] Select and document the narrowest useful client workflow, user, problem, and measurable outcome.
  - [ ] Lock the architecture, threat model, data classification, and acceptance criteria before implementation.
  - [ ] Build the MVP with authentication, least-privilege access, audit events, and a clear failure/recovery path.
  - [ ] Complete independent security review and QA using retained evidence before pilot access.
  - [ ] Document deployment, support, incident handling, backup, restore, and rollback procedures.
  - [ ] Run a time-boxed pilot and capture client feedback, adoption, defects, and a go/no-go decision.

  ### Acceptance criteria

  - A pilot user can complete the selected workflow end to end without operator intervention for normal cases.
  - All sensitive data flows are documented; authentication, authorisation, audit logging, and retention behavior are tested.
  - 100% of release-critical acceptance tests pass, with security and QA evidence attached to the release decision.
  - A second operator can deploy, support, back up, restore, and roll back the MVP using the documentation.
  - The pilot produces a written outcome decision and a prioritised next-iteration backlog.

  ## G4 — Productise secure service delivery (P3)

  **Accountable owner:** Seamus Walsh  
  **Delivery owner:** CSO agent/security function for controls; CEO agent for offer and commercial packaging  
  **Assurance:** QA agent for reusable evidence packs  
  **Deadline:** 27 November 2026  
  **Dependencies:** G2 operating cadence; G1 secure deployment and recovery controls; G3 portal patterns where they reduce service-delivery friction; confirmed Irish enterprise pilot opportunities.

  ### Tasks

  - [ ] Define GDPR, WEEE, chain-of-custody, certificate, retention, and customer-data handling requirements for the data-destruction service.
  - [ ] Design the repeatable request, approval, evidence, certificate-generation, audit-trail, and retention workflow.
  - [ ] Create a repeatable cybersecurity assessment workflow with scope, evidence collection, findings, remediation, and client sign-off.
  - [ ] Create a B2B resource and onboarding hub that explains the offers, prerequisites, deliverables, and support path.
  - [ ] Package measurable outcomes, assumptions, pricing inputs, and delivery timelines for Irish enterprises.
  - [ ] Run at least two qualified client pilots and convert the results into case evidence and a reusable delivery playbook.

  ### Acceptance criteria

  - Each offer has a documented scope, owner, dependency map, standard inputs/outputs, data-handling rules, and escalation path.
  - WEEE/data-destruction records are traceable from request through certificate and retention/disposal decision.
  - Cybersecurity assessment outputs are reproducible and reviewed before client release.
  - A prospect can understand the offer and start onboarding without bespoke explanation from Seamus.
  - Two pilots produce measurable before/after outcomes, client feedback, delivery effort, and a decision on whether to scale.
